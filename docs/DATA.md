# NSL-KDD data

Use the full official split: `KDDTrain+.txt` (125,973 rows) for training and
five-fold cross-validation, and `KDDTest+.txt` (22,544 rows) for the final test.
The text files have 41 features, an attack label, and a difficulty score, with
no header. They are stored in `data/` and excluded from Git.

Download the files with:

```powershell
python scripts/download_data.py
```

The script downloads from the [defcom17/NSL_KDD public mirror](https://github.com/defcom17/NSL_KDD),
which preserves the full NSL-KDD text splits, and verifies these SHA-256 hashes:

| File | SHA-256 |
|---|---|
| KDDTrain+.txt | `1b86d2f957b33082081bba410fe129b475efebcc13c9014c3f447c8271aadf95` |
| KDDTest+.txt | `fa46b0935342616aa83b7c2578db355b6a7aaabbc492248172c7a1e8b7ab8f84` |

If the mirror is unavailable, obtain the same full text files from the
[NSL-KDD dataset repository](https://github.com/jmnwong/NSL-KDD-Dataset)
and place them in `data/`. Verify their SHA-256 values before training.

## Labels

`normal` maps to binary 0. Every named attack maps to binary 1. Attack-family
labels are for analysis only; the trained model remains binary.

| Family | Attack labels |
|---|---|
| Normal | normal |
| DoS | back, land, neptune, pod, smurf, teardrop, mailbomb, apache2, processtable, udpstorm, worm |
| Probe | ipsweep, nmap, portsweep, satan, mscan, saint |
| R2L | ftp_write, guess_passwd, imap, multihop, phf, spy, warezclient, warezmaster, sendmail, named, snmpgetattack, snmpguess, xlock, xsnoop, httptunnel |
| U2R | buffer_overflow, loadmodule, perl, rootkit, ps, sqlattack, xterm |

The loader rejects unknown attack names. Mapping follows the four KDD attack
families described by [SIGKDD](https://kdd.org/kdd-cup/view/kdd-cup-1999/Tasks)
and the named attacks in these NSL-KDD splits.

## Feature selection

The saved legacy feature list contains 39 of the standard 41 features, omitting
`num_outbound_cmds` and `is_host_login`. Inspection of these exact files found
`num_outbound_cmds` is zero in both splits. `is_host_login` is **not constant**:
it is 1 in one training row and 11 test rows. We omit both to preserve the
existing 39-feature interface; the original feature-selection rationale is
unavailable.

Categorical encoders and the scaler are fitted only on training data. During
cross-validation they are fitted separately inside each training fold. An
unseen test category is encoded as `-1` for evaluation; the sample app reports
unknown input categories rather than silently accepting them.

## Phase 3 sample upload

`data/sample_traffic.csv` contains the first ten normal and first ten anomaly
rows from the official `KDDTest+.txt` split. It includes the 39 model features
and `label_binary`, so Batch Scan can show threshold-dependent precision and
recall. It was generated by `python -m scripts.create_sample`. These rows are
examples for testing the upload workflow, not a new validation split.
